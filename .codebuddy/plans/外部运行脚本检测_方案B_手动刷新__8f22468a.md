## 用户需求

为 npm-run 扩展增加“外部脚本运行状态检测”能力：用户在其他 IDE 或终端执行 `npm run dev` 等脚本时，本扩展列表中对应脚本在**手动点击刷新**后显示为运行状态。不采用常驻自动监听（避免性能开销），检测为快照式、按需触发。

## 产品概述

点击树视图刷新按钮时，扩展对系统做一次进程与端口快照，将外部运行的 npm 脚本匹配回列表中的项目与脚本，以独立状态呈现。同一项目在别处启动的 dev server 可被准确识别（进程命令行携带项目 node_modules 绝对路径作为锚定凭据），并展示其监听端口。

## 核心功能

- **三态脚本行**：未运行 / 运行中（本扩展启动）/ 外部运行中（实心圆图标，描述含 PID 与检测时间；无路径凭据的同名匹配标注“疑似”）
- **外部端口子节点**：外部进程子树内监听的端口以只读服务条目展示（地址、PID）
- **运行前警告**：对外部运行中的脚本点击运行时弹窗提示已有外部进程，可选择继续或取消
- **结束外部进程**：外部脚本行提供结束按钮，二次确认后按 PID 结束进程树
- **状态语义诚实**：检测结果为刷新时刻快照，tooltip 注明命令行摘要与“不自动更新”
- 现有功能（自身实例管理、单服务重启、双语文案）完全不受影响

## 技术栈

- 复用现有栈：TypeScript + VSCode Extension API + esbuild + mocha，零新依赖
- 新匹配模块遵循 processTree/serviceDiff 先例：纯逻辑、不依赖 vscode、可单测

## 实现方案

### 检测流程（refresh 命令编排）

```mermaid
flowchart LR
  A[点击刷新] --> B[scanner.refresh 重扫项目]
  B --> C[进程快照 + 端口快照 并行]
  C --> D[排除本扩展实例子树]
  D --> E[cmdline 证据分级匹配]
  E --> F[externalRunning Map 更新]
  F --> G[树视图三态渲染]
```

### 匹配算法（分级证据）

1. **排除集**：用现有 `collectSubtreePids` 对各实例 `rootPid` + `adoptedPids` 子树求并集，排除本扩展自己启动的进程
2. **A 级（项目锚定）**：cmdline 规范化（Windows 统一大小写与斜杠方向）后含 `<项目目录>\node_modules\` → 项目确定；沿父链（深度上限约 6）查找 `npm-cli.js / pnpm.cjs / yarn run <script>` 特征层取脚本名（词边界正则防 `dev` 误配 `dev:watch`），校验脚本名存在于 project.scripts → 确定命中
3. **B 级（仅脚本名）**：只有包管理器 run 特征、无路径凭据 → 候选 = 含该脚本的全部项目；唯一候选视为确定，多候选逐个标 `ambiguous: true`（"疑似"）
4. **端口关联**：命中 pid 子树内的 `ListeningSocket` 归入 `hit.ports`

### 关键决策与权衡

- **externalRunning Map 保持单实例引用**（clear + set 而非重新赋值），treeProvider 持引用每次 getChildren 读取，避免引用失效
- **生命周期**：自身实例启动成功后删除对应 external 条目（避免自身停止后陈旧状态复现）；scanner.refresh 后项目消失的条目同步清理；快照失败静默跳过（对齐现有 handleConflict 行为）
- **性能**：匹配为 O(进程数 × 项目数) 内存操作（典型 <1ms）；快照成本等于现有监控一个 tick，仅在点击刷新时发生，无新增常驻定时器
- **纯模块边界**：externalDetect.ts 接收 `ProjectRef { dir, scripts }` 最小结构（调用方由 NpmProject 映射），避免引入 vscode 依赖，延续可单测先例

## 实施要点（防回归）

- treeProvider 判定链：`instance ? script-running : (external ? script-external : script)`，自身实例优先；showOutput 对 external 行天然安全（可选链兜底）
- package.json 菜单需为 `script-external` 补 `runScript`（内联 ▶）与 `killExternal`（内联 ✕）两条 view/item/context 规则，否则新 contextValue 无任何按钮

## 关键代码结构

```typescript
/** src/externalDetect.ts — 外部运行命中结果 */
export interface ExternalHit {
  projectDir: string;       // 命中项目根（fsPath）
  script: string;           // 命中脚本名
  pids: number[];           // 匹配到的进程（npm 层或执行层 pid）
  cmdline?: string;         // 证据命令行（tooltip 展示）
  ambiguous: boolean;       // true = 仅同名匹配无路径凭据（"疑似"）
  detectedAt: number;       // 检测时间戳
  ports: { port: number; pid: number; addresses: string[] }[]; // 子树内监听端口
}

/** 纯匹配入口：返回 key（`${dir}|${script}`，与 instanceKey 同构）→ ExternalHit */
export function matchExternalScripts(
  procs: ProcessInfo[],
  sockets: ListeningSocket[],
  projects: readonly ProjectRef[],
  excludeSubtrees: ReadonlySet<number>
): Map<string, ExternalHit>;
```
