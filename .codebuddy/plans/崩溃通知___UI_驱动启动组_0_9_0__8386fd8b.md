## 用户需求

为 npm-run Manager（VSCode 扩展，当前 0.8.5）新增两个功能，约束：改动最小、不影响现有功能。

## 产品概述

1. **崩溃通知**：脚本非正常退出时（非用户主动停止 && 退出码非 0），当前只有输出面板里一行文字和树图标变化，用户无感知；补一条编辑器通知弹窗，点击「查看输出」直达报错日志。
2. **启动组**：monorepo 下经常需要依次手动启动多个项目的 dev 脚本；新增「启动组」——右键脚本行「添加到启动组」收集成员（UI 驱动，不让用户手写 JSON），树顶部显示组节点，▶ 一键并行启动全部成员；组可删除、成员可移除。

## 核心功能

- 崩溃通知：仅异常退出触发（正常 exit 0、用户主动 stop/重启、扩展代管转换均不打扰），通知带跳转输出按钮
- 启动组管理：脚本行右键添加进组（QuickPick 选已有组或新建）；组行展开可见成员，成员行可移除；组行右键可删除组（modal 确认）
- 一键启动组：跳过已在运行（幂等）与外部运行中（不弹确认窗）的成员，结束后一条汇总通知（已启动 x · 跳过 y · 未解析 z）
- 配置持久化到工作区 settings.json 的 `npm-run.groups`，UI 操作自动回写，手写配置亦可共存；改配置即时生效

## 技术栈

沿用现有栈：TypeScript + VSCode Extension API（TreeView/Configuration/QuickPick），esbuild 构建，mocha + node:assert 测试。不引入任何新依赖。

## 实现方案

### 功能一：崩溃通知（约 40 行，纯增量）

现有 `onExit` 无法区分「自己挂了」与「被用户停止」（两者都走 close → finish → onExit）：

- `src/types.ts`：`RunningScript` 加 `userInitiatedStop?: boolean`
- `src/runner.ts` `stop()`（L159-184）：kill 前对 `runningInstances.get(key)` 设标志；若 `killProcessTree` 返回错误（进程未死、close 不会触发）则回滚标志，防止下次真崩溃被误判漏报
- `src/extension.ts` `runnerEvents.onExit`（L103-117）：在 adopted 分支 return 之后，`!instance.userInitiatedStop && code !== 0`（含 null，被外部杀）→ `showErrorMessage(t.crashNotified(...), t.showOutput)`，选中按钮 → `instance.output.show()`
- 重启流程天然正确：stop 设标志静默退出 → start 创建全新实例对象（无标志）

### 功能二：启动组（新文件 + 约 200 行增量）

- **配置 schema**（package.json）：`npm-run.groups`，type object、default {}、值为 string 数组；回写用 `getConfiguration('npm-run').update('groups', v, ConfigurationTarget.Workspace)`
- **解析模块**（新文件 `src/launchGroups.ts` 纯函数，不依赖 vscode，可单测）：
- ref 格式 `项目:脚本`，分隔符取 `lastIndexOf(':')`（防脚本名含冒号）
- 项目匹配：优先 workspace 相对路径匹配 `project.dir`；兜底 package.json `name`（仅唯一命中才认，重名宁可不解析）；script 必须在项目声明中
- 未解析成员保留显示（标 ⚠），不导致组消失
- **树结构**（`src/treeProvider.ts`）：TreeNode 加 `launch-group`（icon rocket，description「n 个脚本」，tooltip 列成员，可展开）与 `group-member`（显示「项目名 · 脚本名」，未解析灰色 ⚠）；`getChildren(根)` 在 projects 之前平铺组节点（仅有组时）；provider 构造函数注入 `() => 配置读取器`（与 runner 的 extraEnv 同模式）
- **命令**（package.json + extension.ts）：
- `npm-run.runGroup`：组行 inline ▶ → 逐成员复用 startScript；已在运行跳过、外部检测命中的成员跳过（不弹确认窗，避免打断与端口冲突）；完成后一条汇总通知
- `npm-run.addToGroup`：script 与 script-running 行 context menu → QuickPick（已有组 + 「＋ 新建组…」输入框），回写配置
- `npm-run.removeMember`：成员行 inline ✕，回写配置
- `npm-run.deleteGroup`：组行 context menu，modal 确认后删组，回写配置
- **菜单 when**：沿用现有 viewItem 显式分流模式；`launch-group`/`group-member` 各自新增 when 条目
- **热生效**：现有 `onDidChangeConfiguration` handler（L47-55）追加 `npm-run.groups` → `provider.refresh()`
- v1 不做「端口就绪再启下一个」依赖顺序，纯快速连发

## 执行注意

- i18n 字典值支持函数占位参数，新文案按现有分区注释风格（── 崩溃通知 ──、── 启动组 ──）插入 zhDict 与 enDict，key 两边必须对齐
- runner 的 userInitiatedStop 路径涉及 stop→close→finish 异步链，改动时勿触碰 finish() 的 adopted 分支语义
- 版本号三处对齐（package.json + package-lock 两处），CHANGELOG 先确认 0.8.5 已发布再加新段（教训来自记忆）
- 发布相关操作（VSIX/市场）不在本次计划内，仅本地验证
