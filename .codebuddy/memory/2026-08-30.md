## 发布操作要点（本仓库踩坑）

- **环境变量不跨 execute_command 保留**：必须把 `$env:VSCE_PAT='...'` 与 publish 写在同一条命令内

## 提交信息"乱码"排查结论（2026-08-30）
- 用户在自己终端看到提交信息乱码，但**仓库存储是正确的 UTF-8**：`git cat-file commit HEAD` 取原始字节验证（`e69bb4`=更、`e78eaf`=环），`i18n.commitEncoding`/`logOutputEncoding` 均未配置（默认 UTF-8）
- 真因是 Windows 控制台代码页 936（GBK）解析 UTF-8 字节 → 显示乱码。解法**不要动 git 配置**（规则禁止），用 `chcp 65001` 切当前会话代码页，或用 Windows Terminal / VSCode 集成终端（默认 UTF-8）
- 排查手法：`node -e "... execSync('git cat-file commit HEAD',{encoding:'buffer'})..."` 打印 hex；用 `new TextDecoder('utf-8',{fatal:true})` 批量校验改动文件是否为有效 UTF-8 且无 BOM（本次 9 个文件全部 OK）

## Git 提交踩坑（本仓库会反复遇到）
- **PowerShell 下 `git commit -m "中文"` 会乱码**（UTF-8 被当 GBK 解析）：必须用 `-F <消息文件>`，文件用 write_to_file 写（UTF-8 干净）。第一个提交用 -F 正常、第二个用 -m 直接乱码成"鏇存柊鐜..."就是对比
- **提交信息里不能出现 `$(`**（如 `$(link-external)` 图标名）：PowerShell 双引号串内 `$(...)` 是子表达式，整行解析失败报"字符串缺少终止符"
- **amend / commit 会把 index 里已暂存的 untracked 文件带进提交**：本仓库 `.codebuddy` 已不在 `.gitignore`（见 commit 867174f），其下的每日日志 / plans / 临时 cjs 都是可见未跟踪文件。提交后务必 `git show --stat HEAD` 核对文件列表；混入时用 `git reset HEAD~1`（mixed，工作区不动）撤回后重新显式 add 单个文件
- 提交信息风格沿用仓库惯例：`feat(extension): ...` / `docs(xxx): ...` + 中文描述
